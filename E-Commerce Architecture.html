Authentication & Authorization

JWT lifecycle, OAuth2 social login, token rotation, and RBAC

JWT Login Flow
1
POST /api/auth/login
Client sends { email, password }
2
AuthenticationManager
Spring Security validates via UsernamePasswordAuthToken
3
UserDetailsServiceImpl
Loads user from DB, verifies BCrypt hash
4
JwtUtils.generateTokens()
Access Token (15 min) + Refresh Token (7 days). Refresh stored in DB & Redis
5
Response
{ accessToken } in body, refreshToken in httpOnly cookie
Request Authorization
1
JwtAuthFilter (OncePerRequest)
Extracts Bearer token from Authorization header
2
Token Validation
Verifies signature, expiry; checks Redis blacklist for revoked JTIs
3
SecurityContextHolder
Sets UsernamePasswordAuthToken with UserDetails and granted authorities
4
@PreAuthorize
Method-level RBAC guards — hasRole('ADMIN'), hasRole('SELLER')
5
@AuthenticationPrincipal
Controller receives authenticated UserDetails
Token Refresh & Rotation
1
Access token expires → 401
Client intercepts 401 Unauthorized
2
POST /api/auth/refresh
Sends refresh token from httpOnly cookie
3
DB Validation
Check refresh_tokens: not revoked, not expired, matches user
4
Token Rotation
Old refresh token revoked in DB; new pair issued (prevents reuse)
5
Retry original request
Client queues and retries failed requests with new access token
OAuth2 Google / GitHub
1
GET /oauth2/authorize/google
Spring Security redirects to provider consent screen
2
Callback with auth code
Provider redirects to /oauth2/callback/google with code
3
CustomOAuth2UserService
Fetches user profile from provider, upserts local users record
4
Issue JWT pair
Same flow as password login; returned via redirect params to client

application.yml — Kafka
spring:
  kafka:
    bootstrap-servers: localhost:9092
    producer:
      key-serializer: org.apache.kafka.common.serialization.StringSerializer
      value-serializer: org.springframework.kafka.support.serializer.JsonSerializer
      acks: all          # wait for all replicas to acknowledge
      retries: 3
    consumer:
      group-id: ecom-notification-group
      auto-offset-reset: earliest
      key-deserializer: org.apache.kafka.common.serialization.StringDeserializer
      value-deserializer: org.springframework.kafka.support.serializer.JsonDeserializer
    listener:
      ack-mode: MANUAL_IMMEDIATE  # manual commit for at-least-once delivery

Redis Cache Strategy

Key patterns, TTL policies, data types, and eviction rules

Session Store
session:{userId}:{sessionId}
→ HASH { roles, ip, userAgent, lastActivity }
TTL: 30 min slidingType: HASHEvict: LRU
JWT Blacklist
jwt:blacklist:{jti}
→ "revoked"
TTL: = token expiryType: STRINGUse: Logout
Shopping Cart
cart:{userId}
→ HASH { productId: { qty, price, name } }
TTL: 7 daysType: HASHSync: checkout → DB
Rate Limiting
rate:{ip}:{endpoint}
→ request_count (INCR + EXPIRE)
TTL: 60 s windowType: STRINGLimit: 100/min
Product Cache
product:{productId} → JSON
category:{id}:products → LIST of IDs
TTL: 10 minType: STRINGEvict: on update
OTP Store
otp:{email}
→ HASH { code, attempts, type }
TTL: 5 minType: HASHMax attempts: 3
Popular Products
leaderboard:products:views
→ ZSET { productId: view_score }
TTL: 24 h refreshType: SORTED SETQuery: ZREVRANGE
Pub/Sub Real-time
Channel: order-status-updates
Channel: stock-alerts · price-drops
TTL: none (stream)Type: PUB/SUBBridge: STOMP/WS
